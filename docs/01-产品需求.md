# 产品需求

## 背景与推导

舞台文本、排演计划与一次实际演出有不同生命周期。剧本改了，不代表灯光、声音和换景提示已经复核；提示按计划排列，也不证明现场按时执行。工程保存剧本依据、提示触发、调用依赖和独立排演记录，让Agent组织复杂度，导演与作者审阅和决定。

生成成本和等待时间会变化，但固定作品、历史依据、具体意见与连续审阅仍需长期积累。固定工程避免让模型每轮重建结构；结构化数据与多种阅读方式共用同一专业成果。插件按需安装，让作者提出目标、Agent操作工程、作者在适合的工作面阅读和选择。

## 定义与首版

舞台排演是河图洛书JS／TS专业插件。把固定剧本、部门提示、调用依赖和真实手记组织成可回读的排演提示本。用户包括独立作者、编辑与外部Agent。默认旅程：读取固定剧本 → 段落与部门提示 → 核对调用依赖 → 比较提示编排 → 保存手动排演记录 → 复核改稿影响 → 提示本与固定交接。

首版包含完整专业维护、准确来源回读、并行方案、固定意见、专业状态和改稿影响、上下文、固定交接、JSON／Markdown／HTML工程及专业阅读本。功能必须经机器入口执行，作者可以自然语言提出目标，也保留人工优化入口。

## 边界

宿主剧本保存正式文本，导演布景台负责空间与机位，本包负责现场提示本和排演复盘。不控制灯光、音响或舞台机械，不承担现场安全调度和对外演出发布。正文、正式设定、素材、采纳与定稿由宿主和作者掌握，不另建数据库、模型渠道或内部Agent。

成功以真实创作、审阅、返工及下一轮接续为准，安装、动作数或文件存在都不足以代表完成。开发与验收状态只由08维护。
